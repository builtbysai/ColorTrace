# ColorTrace security and privacy model

ColorTrace separates temporary page authority from persistent evidence. Page inspection requires an explicit user gesture that grants `activeTab`; `scripting` is used only to inject the unlisted inspector into that tab. No persistent host grants are requested.

The trace firewall is a construction boundary, not a redaction pass. It accepts a fixed set of color-bearing computed properties and constructs only fields representable by the strict v1 schema. Low-exposure fingerprints omit IDs and classes because these can encode personal or application-specific identifiers. Source acquisition is property-specific and bounded: accessible top-level author rules are inspected only for the traced property, with hard caps on stylesheets, visited rules, and persisted matches. Selector text is used transiently only to evaluate whether a rule matches the selected element and is never persisted or exported; matched-rule evidence stores the declaration value and `!important` priority with selector provenance explicitly withheld. Cross-origin or otherwise inaccessible stylesheets remain unknown rather than motivating broader host permissions.

Persistence is extension-origin IndexedDB. Data never uses browser sync storage and the production implementation contains no network transport. Export is an explicit user action implemented with an in-memory Blob and an object URL, so the extension does not need the `downloads` permission.

Threat model: a hostile page may control CSS strings, selectors, and DOM metadata. Persisted strings are schema-bounded; raw selector identifiers/attribute values, page text/HTML/form/cookie data are structurally absent from low-exposure traces; and restricted pages fail closed. Matching CSS rules are evidence that a declaration exists and its selector matched the target at capture time, not proof that the declaration won the cascade. This MVP does not claim to protect against a compromised browser profile or extension runtime.
